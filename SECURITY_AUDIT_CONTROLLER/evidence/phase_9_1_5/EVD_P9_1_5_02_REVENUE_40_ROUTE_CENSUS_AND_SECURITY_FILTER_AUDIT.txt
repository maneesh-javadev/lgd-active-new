Key Architectural Proof:
  1. Unauthenticated requests to ANY route outside /public/v1/** are intercepted by
     JwtAuthenticationFilter and SecurityFilterChain BEFORE reaching Spring MVC DispatcherServlet.
  2. Therefore, unauthenticated probes return HTTP 401 regardless of whether TestController
     is active, present, or absent in the ApplicationContext!
  3. Testing ONLY with unauthenticated probes proves Spring Security is active, but proves
     ZERO about whether TestController bean exists or is exposed.
  4. To test whether TestController is excluded by @Profile({"dev", "test"}), the request MUST
     pass Spring Security with a valid authenticated JWT Bearer token.
  5. When authenticated, Spring Security allows the request to reach DispatcherServlet.
     DispatcherServlet looks up RequestMappingHandlerMapping. If TestController is omitted,
     DispatcherServlet returns true HTTP 404 Not Found.

5. ACTUATOR VS. APPLICATIONCONTEXT REFLECTION DECISION:
--------------------------------------------------------------------------------
Option 1: Add spring-boot-starter-actuator to revenue/pom.xml
  - Pros: Exposes /actuator/mappings for declarative REST inspection.
  - Cons: Requires modifying POM file (violates read-only policy); expands attack surface
    (exposing actuator endpoints in production); introduces potential security exposure.
Option 2: Restricted Spring ApplicationContext Reflection Test (RECOMMENDED)
  - Pros: Zero POM modification; executes during test lifecycle; inspects BeanFactory
    directly via 'context.containsBean("testController")' and
    'mappingHandlerMapping.getHandlerMethods()'; zero production attack surface expansion.
  - Cons: Requires executing test runner rather than an external HTTP curl.
Recommendation:
  Adopt Option 2 (Restricted Spring ApplicationContext reflection test) for automated
  regression and combine with authenticated HTTP 404 probes during Stage B runtime.
