--------------------------------------------------------------------------------
PowerShell Output (Get-NetIPAddress):
  - Interface: 'vEthernet (WSL (Hyper-V firewall))'
    IPv4: 172.20.32.1 / Prefix: 20 (Subnet: 172.20.32.0/20)
    IPv6: fe80::584f:3746:b3a3:c3c7%43 / Prefix: 64 (Link-Local)
  - Interface: 'Loopback Pseudo-Interface 1'
    IPv4: 127.0.0.1 / Prefix: 32
    IPv6: ::1 / Prefix: 128
Hazard:
  In default WSL2 architecture, the Hyper-V virtual switch allocates an ephemeral subnet
  (from the 172.16.0.0/12 block) upon host reboot. If PostgreSQL hardcodes '172.20.32.1'
  and the interface rebinds to '172.24.48.1' after reboot, PostgreSQL fails to bind
  the socket and refuses to start (WSAEADDRNOTAVAIL).
  Using 'listen_addresses = "*"' is permanently PROHIBITED as it binds to all public NICs.

3. DYNAMIC WSL2 PRE-STARTUP DISCOVERY ALGORITHM (FAIL-CLOSED):
--------------------------------------------------------------------------------
The pre-startup script executes BEFORE Start-Service postgresql-x64-14:
  Step 1: Identify WSL Interface: Query Get-NetAdapter where Name -like "*WSL*".
  Step 2: Read Actual IPv4 Address: Extract IPAddress from Get-NetIPAddress -AddressFamily IPv4.
  Step 3: Validate Interface Identity: Confirm adapter description matches Hyper-V Virtual Ethernet.
  Step 4: Approved Range Check: Assert IP matches Approved Regex ^172\.(1[6-9]|2[0-9]|3[0-1])\.
  Step 5: Dynamic Listener Substitution: Inject verified IP into postgresql.conf:
          listen_addresses = '127.0.0.1, <DETECTED_WSL_IP>'
  Step 6: Dynamic pg_hba.conf Alignment: Inject corresponding /20 subnet into hostssl rule.
  Step 7: Fail-Closed Trap: If WSL interface is missing, disabled, or IP is outside approved
          RFC 1918 range, ABORT STARTUP IMMEDIATELY and log diagnostic event.
  Step 8: Manifest & Event Log: Record SHA-256 of updated configuration before launching service.
