2. CONNECTION POOLING (COMMONS-POOL2) CENSUS:
--------------------------------------------------------------------------------
Audit Finding:
  - 'org.apache.commons:commons-pool2' is COMPLETELY ABSENT from all POM files.
  - Spring Boot auto-configuration class 'LettuceConnectionConfiguration' evaluates:
      ClassUtils.isPresent("org.apache.commons.pool2.impl.GenericObjectPool", classLoader)
  - Because commons-pool2 is missing, any configuration under 'spring.data.redis.lettuce.pool.*'
    (max-active, max-idle, min-idle, max-wait) is SILENTLY IGNORED.
  - Runtime Consequence:
      Lettuce operates exclusively via multiplexed, single shared TCP connections.
      While this is standard and optimal for reactive 'api-gateway', blocking services
      ('revenue', 'user-management', 'auth-service') under high concurrent transactional loads
      cannot establish pooled connections without adding 'commons-pool2'.

3. LETTUCE CUSTOM CA TRUSTSTORE DESIGN GAP (DISC-P913-02):
--------------------------------------------------------------------------------
Phase 9.1.2 Proposed Java Customizer:
  builder.useSsl()
         .and()
         .commandTimeout(Duration.ofSeconds(3))
         .shutdownTimeout(Duration.ofMillis(100));

CRITICAL SECURITY & COMPILATION DEFECT ANALYSIS:
  - In Netty / Lettuce, calling 'builder.useSsl()' activates TLS using default Java
    TrustManagerFactory which resolves '$JAVA_HOME/lib/security/cacerts'.
  - In PostgreSQL, the JDBC driver takes 'sslrootcert=/etc/ssl/certs/lgd-internal-ca.crt'
    directly in the URL.
  - IN REDIS / LETTUCE, THERE IS NO URL PARAMETER FOR CA ROOT CERTIFICATES.
  - Because the Redis Sentinel cluster uses internal certificates signed by the private
    LGD Internal CA, and this private CA is NOT in the default Temurin JRE 'cacerts',
    Lettuce throws a fatal runtime exception during TLS handshake:
      javax.net.ssl.SSLHandshakeException: PKIX path building failed:
      sun.security.provider.certpath.SunCertPathBuilderException:
      unable to find valid certification path to requested target
  - The Stage B blueprint OMITTED instructions on how Lettuce will validate the private CA!

REQUIRED BLUEPRINT CORRECTION:
  Option A (Recommended for Containers):
    Import 'lgd-internal-ca.crt' into the container JVM truststore during Docker build:
    RUN keytool -importcert -noprompt -keystore "$JAVA_HOME/lib/security/cacerts" \
        -storepass changeit -alias lgd-internal-ca -file /etc/ssl/certs/lgd-internal-ca.crt
  Option B (Spring Boot 3.1+ SSL Bundles):
    Define 'spring.ssl.bundle.pem.redis.truststore.certificate=/etc/ssl/certs/lgd-internal-ca.crt'
    and configure 'spring.data.redis.ssl.bundle=redis'.
