2. SPRING SECURITY FILTER CHAIN INTERCEPTION MECHANICS:
--------------------------------------------------------------------------------
Source Inspected: revenue/src/main/java/in/nic/lgd/revenue/user/security/SecurityConfig.java
Lines 36-39:
  .authorizeHttpRequests(auth -> auth
      .requestMatchers("/public/v1/**", "/swagger-ui/**", "/v3/api-docs/**").permitAll()
      .anyRequest().authenticated()
  )
Lines 27-31:
  .authenticationEntryPoint((request, response, authException) -> {
      response.setStatus(HttpServletResponse.SC_UNAUTHORIZED); // 401
      response.setContentType("application/json");
      response.getWriter().write("{\"error\": \"Unauthorized\", \"message\": \"Authentication token is missing or invalid\"}");
  })

Critical Technical Discovery:
  - In Spring Security, the security filter chain executes BEFORE the DispatcherServlet
    determines if a matching handler mapping exists!
  - Because neither '/test/**' nor '/private/v1/test/**' is in the permitAll list,
    any UN涵AUTHENTICATED HTTP request sent to these endpoints is intercepted by
    JwtAuthenticationFilter and immediately returns HTTP 401 Unauthorized!
  - It NEVER reaches the DispatcherServlet!
  - Expecting an unauthenticated probe to return HTTP 404 is technically impossible.
  - An unauthenticated probe returning 401 confirms security filter enforcement,
    but DOES NOT prove that the controller bean was excluded by @Profile.
  - To prove that the controller bean was NOT instantiated (returning 404),
    the probe MUST include a valid authenticated JWT Bearer token:
      Authorization: Bearer <VALID_JWT_TOKEN>
    When the valid token passes JwtAuthenticationFilter, DispatcherServlet evaluates
    handler mappings. Because @Profile({"dev", "test"}) prevented bean creation under 'prod',
    DispatcherServlet returns HTTP 404 Not Found!
